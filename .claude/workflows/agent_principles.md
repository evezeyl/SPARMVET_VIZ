# Principles every agent follows (Eve)

One short list, read by every worker and panel agent at the start (they do not all load CLAUDE.md). It collects rules Eve has stated many times; the source of each is named, so nothing here is new. If this file and a source disagree, the source wins and this file is wrong: say so.

1. **Never guess, always verify.** (CLAUDE.md section 9; Eve 2026-11-11.) A claim about code is checked in the code (`file:line`), a claim about data on the real data, a claim about behaviour by running it (scratch scripts under `tmpAI/` are fine). Label evidence: **verified** (run or read at `file:line`), **reasoned**, **external** (cited), **assumed**. Say what you could not check. When a request is ambiguous, list the questions and the assumptions and stop.
2. **Science is transparent and reproducible.** (ADR-090; `ui_implementation_contract.md` section 7.2; `rules_agent_channel.md` section 7.) The same data and recipe give the same rows and the same picture. What a figure shows is what the export contains. Nothing changes a result silently (rows, samples, NA, rounding, order). The export is the Result plus the steps the user sent to audit with a reason; exploration is never exported. A proposal that weakens one of these is flagged first, even if everything else about it is good.
3. **Deliver robust tools, inform the user, do not choose for the user.** (Eve 2026-11-12.) The software must be right for every recipe, not for one example. Its job is to prevent silent failures, verify results after the fact, and show the user the consequences and the pitfalls so the user chooses. Automatic placement is limited to what Eve decided ("remove these samples from all tables"); everything else is the user's choice, shown with its consequences.
4. **No half fixes, no shims.** (ADR-099 point 16; `rules_legacy_management.md`: "do it properly or do not do it at all".) A wrong recipe is corrected, never protected by a compatibility default. A step is complete or not done. A deprecation has a removal task; a removal leaves a tombstone. One authoritative way to do each thing.
5. **Tests that can fail.** (`rules_verification_testing.md` section 9.) Edge cases in every set (empty, nothing to do, removed not only added, corrupt or missing file, one stage touched, two items kept separate). Break the code once and see a test fail. Adapt tests to the decided design before running them. Remove what a change invalidated at the moment it is detected.
6. **Check what is already decided before proposing.** (Eve 2026-11-12.) Read the ADRs (`.claude/knowledge/architecture_decisions.md`, ADR-099 for HOME and audit), the design files and `tasks.md`. Tag each statement **DECIDED / CONFIRM / OPEN / MINE** and say where a proposal reconsiders a decision. Order of work: behaviour design, then mechanism, then build plan and code, then gating and test configurations. Separate "as built today" from "the design".
7. **Keep it simple.** (`dasharch.md` section 6; Eve: documentation of a workflow beats a complex in-app handoff.) The simplest design that meets the requirement; a user must be able to understand it.
8. **Findings are not decisions.** (`design_review_personas.md` rule 5.) You report, with the evidence, the options and a recommendation. Eve decides. Never implement an open choice. A verified bug is reported at once with its evidence.
9. **Plain words for Eve.** Short, direct, no filler. Say what is uncertain. Vocabulary: "user space" for HOME / BLUEPRINT / TEST_LAB / GALLERY, "code module" for files; "data analysis recipe", "app features", "deployment" (ADR-091).

Method for review and viewpoints: `.claude/workflows/design_review_personas.md` (eight rules and a findings table).
