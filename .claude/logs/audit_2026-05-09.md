## Decisions Made

### Execution model: local over cloud (ADR-080)

**Decision:** All audit scripts run locally via systemd user timers, not Claude Code cloud `/schedule` Routines.

**Rationale:** Cloud runners have no `.venv/`, no local data files, and only see pushed commits. The audit scripts require all three. Cloud Routines are appropriate only for reasoning-level checks (changelog consistency, phase ordering) that do not need Python execution.

### Systemd timers with `Persistent=true`

**Decision:** Use systemd user timers instead of crontab. `Persistent=true` causes missed runs (PC off/suspended) to fire immediately on next boot.

**Why not cron:** cron silently discards missed runs. For a developer laptop that is regularly closed, this means most scheduled audits would never execute.

### Session-end quick run as primary manual trigger

**Decision:** Documented a four-script session-end quick run (cross-lib, deps-verify, task-drift, template-flags) as the primary manual trigger pattern. These four are fast (~seconds each) and cover the most common sources of drift.
