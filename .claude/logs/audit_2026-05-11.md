## Session 1 — Direction C: ADR-079 (Runtime Error Discipline)

### Decisions

1. **`PipelineError` sits alongside `DeploymentError`, not subclassed.** Shared 5-field shape (component, problem, location, fix, who) is a *convention*; the audience model and render machinery are intentionally different.
2. **Audience model extended.** ADR-078's `operator`/`developer` set is extended with `analyst` (UI inputs / uploaded file), `data_provider` (TSV content), `manifest_author` (YAML author). Routing is the error-raiser's responsibility because only it has the context (e.g., a "column not found" in `DataWrangler` is `manifest_author` if from manifest, `analyst` if from T3 sandbox).
3. **Render surface is per-category.** Five surface values: `plot_overlay`, `notification`, `audit_panel`, `data_import_panel`, `blueprint_inline`. Decoupled via `make_render_payload()` so library code never imports Shiny.
4. **Evidence is a free-shape dict** with conventional keys (`sample_rows`, `offending_value`, `expected_schema`/`actual_schema`, `near_match`). Hard caps: 5 sample rows, 50 schema columns. Privacy line: server-only by default; export only when bundle scope includes affected plots.
5. **Audit-trail capture via new `session_pipeline_errors` reactive value** in `server.py`. Written into `report.qmd` as "Pipeline Issues During Session" section after the T3 Audit Trail (extends ADR-069). Persisted in T3 Ghost as `pipeline_errors:` list.
6. **Backward compatible.** Existing `SPARMVET_Error` subclasses (`IngestionError`, `TransformationError`, `VisualizationError`, `ManifestError`) keep their constructors and gain optional `to_pipeline_error()` adapter. Library APIs unchanged.

### Why this design (the false starts)

- **Considered:** subclassing `DeploymentError` to inherit the format/exit helpers. Rejected because the audience field would have to absorb both startup audiences (`operator`/`developer`) and runtime audiences (`analyst`/`data_provider`/`manifest_author`) in a single value-set — losing the clarity that motivated ADR-078 in the first place. Sibling dataclass keeps each ADR's `who` set semantically clean.
- **Considered:** rendering all runtime errors through `ui.notification_show()` (toast only). Rejected because a plot that fails to render needs the failure visible *where the plot was* — not as a transient toast. A peer reviewer reading an exported session needs the same — silent absence of a plot in the bundle is misleading. Per-category surface is non-optional.
- **Considered:** capturing evidence as free text. Rejected because exporting structured evidence to `report.qmd` produces a far more reviewable Methods appendix; the dict shape with conventional keys is the contract that lets export use rich tables instead of opaque blobs.

## Session 2 — VIZFAC-PLOT-CASCADE-1 (Plot Configuration Cascade)

### Decisions

1. **Five-tier cascade, one merge point.** L5 (T3 `aesthetic_override`) > L4 (`spec:`) > L3 (optimisation, computed) > L2 (`plot_defaults:`) > L1 (built-ins). Resolved by new pure function `resolve_plot_config()` in `libs/viz_factory/src/viz_factory/plot_config_resolver.py`.
2. **Closes the silent T3 gap.** Today `t3_plot_overrides[plot_id]` is recorded, exported, and rendered in the audit panel — but **never applied to the plot itself**. The cascade gives it a defined seam at L5. This is the load-bearing motivation for the design.
3. **Optimisation layer (L3) scope locked.** Visual/aesthetic only — never changes mapping, geom, filters, palette. Current `_auto_adjust_axis_labels()` becomes the entire L3 implementation; per-axis manifest guard becomes implicit via tier dedup. Future heuristics (density jitter, panel spacing, legend ncol) reserved as opt-in flags in `plot_defaults.optimisation:` — not implemented in initial cascade.
4. **`layers:` list is special.** Append-then-deduplicate by `(layer_kind, target)` keeping LAST occurrence (so L5 wins on theme/coord/facet/scale/element_text). `geom_*`/`stat_*` never deduplicated — they accumulate.
5. **L5 `aesthetic_override` gets a fixed schema** (design §6): `fill_color` ⊕ `fill_palette` (mutex with warning), `color`, `alpha`, `shape`, `size`, `theme`. `plot_scope` MUST be a single plot_id (cross-plot propagation = multiple nodes via existing dialog). Other T3 node types operate on data and don't go through the cascade.
6. **`plot_defaults:` schema explicit.** §7a documents allowed keys. Unknown keys emit `PipelineError(severity: warning, who: manifest_author, surface: notification)` per ADR-079 — non-fatal, visible.
7. **Path B (two-pass render) preserved as future option.** L3 stays a pure function of `(seed, raw_spec, df_collected)`; two-pass would be additive (`low_quality_figure` arg).

### Why this design

- **Considered:** keeping the current three-merge-points architecture (`_standardize_config` for plot_defaults, `_apply_palette` for palette, `_auto_adjust_axis_labels` for axis text). Rejected because adding T3 `aesthetic_override` would mean a **fourth** merge point with cross-tier interactions (T3 palette overrides spec palette overrides plot_defaults palette). Single-merge-point cascade is the only design that scales.
- **Considered:** putting optimisation (L3) above spec (L4) so auto-rotation always fires. Rejected because the user's intent in writing an explicit `element_text` layer is to override the heuristic — the heuristic must yield to explicit choice. Optimisation is L3 (between spec and defaults) so it fills gaps without overriding intent.
- **Considered:** allowing L5 to mutate `mapping` or `factory_id`. Rejected because aesthetic overrides are *visual* — changing the mapping would be a different operation (different node type, different audit semantics). Locked the L5 schema to keep `aesthetic_override` semantically distinct from a hypothetical `mapping_override`.
- **Considered:** persona name string check on whether L5 applies. Rejected per ADR-053 anti-pattern. L5 applies whenever `aesthetic_override` is provided; the persona gate is upstream (whether the analyst has T3 sandbox access at all).

## Session 6 — VIZFAC-RESOLVER-1 (2026-05-11)

**Task:** VIZFAC-RESOLVER-1 `[sonnet/high]`

### Files created

| File | Description |

| `libs/viz_factory/tests/test_plot_config_resolver.py` | 75 unit tests covering cascade truth table |

### Design decisions

- **`_normalise_spec()` is pure L4 pre-processing** — it translates `factory_id` to a base geom layer and promotes flat aesthetic keys to `mapping`. It does not merge tiers; it runs before L4 layers are appended so the geom appears first.
- **bar_logic geom selection:** `geom_col` when `y` in mapping, otherwise `geom_bar`. This matches the manifest spec and avoids requiring manifest authors to know the distinction.
- **heatmap_logic remap:** `color → fill` in mapping (plotnine `geom_tile` uses `fill` for the tile colour, not `color`).
- **L3 runs before L4 in layer accumulation** — `compute_optimisation_layer()` is called with L1+L2 seed and `raw_spec` before L4 layers are appended. L4's `element_text` layers are appended afterward, so dedup keeps the last (L4 wins). This is the dedup suppression mechanism tested by `TestL3SuppressedByL4`.
- **`_layer_dedup_key` for `element_text`:** keyed on `("element_text", target)` so x and y axis adjustments deduplicate independently — an L4 x-axis override doesn't eliminate the L3 y-axis size adjustment.
- **L5 fill_color / fill_palette mutex:** when both supplied, `fill_palette` wins and `fill_color` is deleted before processing (not merely ignored). This produces the correct outcome: palette set in seed, no spurious scale_fill_manual layer injected.
- **`_l5_geom_overrides` key:** `color`, `alpha`, `shape`, `size` from L5 are stored in a separate seed key for the render path (VIZFAC-RENDER-WIRE-1) to apply as fixed params on the first geom layer. They are not injected as layers at resolver time because the correct geom to target is unknown at resolver time.

### Design decisions

1. **`generate_fork_yaml` in the library layer** — pure function, zero Shiny, importable from headless scripts (Two-Category Law ADR-045). Takes `raw_config` dict (already resolved by ConfigManager) — no file I/O inside it.
2. **Two render outputs, not one (Rule R4)** — `bp_fork_ui` reads only `active_component_info`; `bp_fork_preview_ui` reads only `_fork_preview_text`. Merging them would cause snap-back: the form widget would destroy itself on every preview update.
3. **`!include` safety gate in `_write_fork_to_manifest`** — `yaml.safe_load()` cannot round-trip manifests with `!include` directives. Inline manifests get auto-write; `!include` manifests get the fragment shown for manual paste.
4. **Idempotent guard on node-change clear (Rule R3)** — `_clear_fork_preview_on_node_change` only calls `_fork_preview_text.set("")` when the value is non-empty, preventing infinite reactive loop.
5. **New ID validation** — `^[a-zA-Z_][a-zA-Z0-9_]*$` regex enforced before calling `generate_fork_yaml`. Prevents IDs that would break YAML keys or Python identifiers.
6. **Phase 18-F now fully complete** — all three bullets (`[x]` clickable nodes, `[x]` IDE form infrastructure, `[x]` Visual Forking).
