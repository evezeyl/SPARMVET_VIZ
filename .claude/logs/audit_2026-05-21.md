## Task 1 — Playwright smoke test fix (test_add_filter_row / test_filter_reset_clears_rows)

Both tests were flaky in the full suite due to a race condition: `filter_form_ui` re-renders
after `active_home_subtab` changes, but the column options come from a LazyFrame scan of the
target dataset parquet. On first navigation, the parquet may not yet exist and the form shows
stale columns from the prior dataset.

**Fix:** Added `_wait_for_fb_col_option(page, "year", timeout=20_000)` helper to
`app/tests/test_shiny_smoke.py`. The helper polls `#fb_col option` via `wait_for_function`
before calling `select_option("year")`. Applied to both `test_add_filter_row` and
`test_filter_reset_clears_rows`.

**Result:** 137 passed, 3 skipped (expected persona skips). All clean.

## Task 2 — ConfigManager-level YAML boolean trap prevention

**Background:** `DataAssembler` has a `step.get(True)` fallback for the unquoted `on:` boolean
trap, but ConfigManager had no prevention — it loaded `True` as a dict key and passed it downstream.

**Fix:** Added `_normalise_yaml_boolean_keys(config, manifest_path)` module-level helper to
`libs/utils/src/utils/config_loader.py`. Called on `self.raw_config` immediately after
`yaml.load()` completes (after `!include` constructors have merged all fragments). The function:
- Recursively walks the entire config dict/list tree
- Converts any `True` dict key to the string `"on"` in place
- Prints a warning naming the manifest file and referencing rules_manifest_structure.md §7

**Verified:** No false positives on the test manifest (all `'on':` are already properly quoted).
Boolean True → string "on" conversion confirmed via unit test.
