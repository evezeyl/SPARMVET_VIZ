## Session 5 — Plot authoring model design (ADR-083) (2026-05-20)

**Trigger:** BP-COMPONENT-FORMS-1 planning surfaced a deeper design question (where do plot/component
nodes commit; how do HOME and BLUEPRINT both configure a plot coherently). User called for a design
pause rather than a hasty layer-parser. No code written this session — design only.

**Key findings (verified in code):**
- The render path ALREADY normalises sugar into a grammar-of-graphics model: `_normalise_spec`
  (plot_config_resolver.py:152) does factory_id→geom-layer + flat-aes→mapping; `resolve_plot_config`
  consumes it. The correct internal model exists — just unnamed/private/non-invertible.
- `factory_id` is a plot-level primary-geom alias (NOT per-layer); legacy from the Visualization Factory
  pattern; no plotnine analogue.
- **tier3 commit bug confirmed:** `_handle_manifest_save_internal` (blueprint_handlers.py:826-828) +
  `btn_download_manifest` (:971) wipe tier1/tier2 and dump the logic stack to `wrangling.tier3`,
  contradicting ADR-082 §4 ("BLUEPRINT never writes T3"). Pre-existing; flagged.

**Decisions documented:**
- New design doc: `.claude/design/plot_authoring_model.md` (the AUTHORING side; companion to
  plot_config_cascade.md, the RENDER side).
- New ADR-083: Canonical Plot Model & BLUEPRINT Authoring Seam. Canonical = mapping + ordered layers
  (geom = layers[0]); shared seam `normalise_plot_spec`/`serialise_plot_spec`; factory_id retired from
  canonical (legacy read-only sugar, never re-emitted); HOME stays narrow L5; tier3 dump is a bug.
- tasks.md resequenced: BP-PLOT-MODEL-1 → BP-PLOT-LOAD-1 → BP-COMPONENT-FORMS-1 → BP-MAPPING-FORM-1 →
  BP-PLOT-COMMIT-1 → BP-PLOT-MIGRATE-1. BP-COMPONENT-FORMS-1 now sits on the new foundation.

**Files modified:** `.claude/design/plot_authoring_model.md` (new), `.claude/knowledge/architecture_decisions.md` (ADR-083), `.claude/tasks/tasks.md` (resequence).
