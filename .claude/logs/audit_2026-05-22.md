**Task:** Upgrade `libs/test_lab/src/test_lab/aqua_synthesizer.py` with two-step API, stress_test mode, and scenario management.

### Implementation

`AquaSynthesizer` class added (replaces scattered module-level functions):
- `propose_config(source, n_rows, mode) → dict` — inspects TSV path or column name list, infers dtype/PK/cardinality, returns config dict
- `generate(config, out_path, seed) → pl.DataFrame` — generates synthetic rows from config; applies error injection in stress_test mode
- `save_config(config, name, scenarios_dir) → Path` — writes named YAML scenario with mandatory "NOT a pipeline manifest" header and `synthetic_data_config:` root key

PK detection: `_is_pk_name()` uses suffix matching (`_id`, `_pk`, `_key`, `_code`, `_num`, `_no`) and exact names (`id`, `pk`, `key`, `accession`, `barcode`, `sample`). "identity" correctly NOT matched.

| `missing_values` | `pl.when(mask).then(None)` on target columns at stated rate |

| `schema_errors` | Append `EXTRA_COL_DO_NOT_USE` column when rate > 0 |
| `malformed_fields` | Inject from `_MALFORMED_STRINGS` list at stated rate in string/categorical cols |

## Addendum 11 — TL-ANON-1 (Anonymiser implementation)

**Task:** Phase 34-F — `libs/test_lab/src/test_lab/anonymiser.py`

### What was built

`Anonymiser` class with two public entry points plus a helper:

- `anonymise(filepath, id_column, personal_columns, pattern, prefix, existing_mapping, out_dir)` — single-file anonymisation. Returns `(anonymised_df, mapping_df)`. Writes TSV + mapping + config YAML when `out_dir` is given.
- `anonymise_batch(filepaths, id_column, ...)` — multi-file batch with shared mapping: all unique IDs collected across all files first, then a single consistent mapping applied. Same `original_id → anon_id` across every file. Returns dict keyed by `"<stem>.tsv"`, `"mapping"`, `"config"`.
- `build_deanon_recipe(id_column, mapping_filename)` — returns a YAML snippet for a BLUEPRINT join recipe to restore original IDs post-anonymisation.

### ID patterns

| Pattern | Format | Example |
|---|---|---|
| `sequential` (default) | `{prefix}_{i:04d}` | `ANON_0001` |
| `hash` | `{prefix}_{sha256[:8].upper()}` | `ANON_A3F9C81B` |
| custom format string | Python `str.format(i)` or `str.format(i=i, original=original)` | `SUBJ_{:05d}` |

### Output files

| File | Description |
|---|---|
| `anonymised_<stem>.tsv` | Original data with IDs replaced; personal cols stripped |
| `mapping_<id_column>.tsv` | `original_<id>`, `anon_<id>`, + personal column values |
| `anonymisation_config.yaml` | Audit record — `anonymisation_config:` root key; `# NOT a pipeline manifest` header |

### Design note

`personal_columns` are stripped where present (best-effort intersection with each file's columns). The `id_column` is the only required column. This allows batch processing of related files that don't all share the same personal column set (e.g. metadata.tsv has name/address; results.tsv doesn't).
