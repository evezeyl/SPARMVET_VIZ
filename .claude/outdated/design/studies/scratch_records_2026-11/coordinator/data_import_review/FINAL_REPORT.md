## DEFECTS (HOME, Data Import)
**D1 (HIGH, fix first). "Accepted if and only if the ingestion reads it" is false: the check does not read the whole file.** VERIFIED by run (`counter.py`, copies under pytest-style temp dirs, nothing in the repo written). The check ends with `lf.collect_schema()` (`ingestor.py:133`, header only); `apply_declared` collects only the columns whose declared type is not String (`declared.py:130,133`; Polars reads only those columns). A file whose damage is in the row structure or in a String column passes and is written over the data file; the next build then fails:
| file (demo-like recipe, copies) | Data Import | engine afterwards |
|---|---|---|
| String-only dataset, non-UTF-8 byte | ACCEPTED | FAILS `ComputeError: invalid utf-8 sequence` |
| a row with one extra field (dataset W, String only) | ACCEPTED | FAILS `found more fields than defined in 'Schema'` |
| same, dataset T (has an Int64 column) | ACCEPTED | FAILS (same) |
| unterminated quote | ACCEPTED | FAILS `could not parse ... as dtype str` |
(Non-UTF-8 in a dataset with a non-String column is refused only by luck: that column is read.) So the panel says "imported", the old file is gone with no copy, and the recipe cannot be built. This was already true before the branch (same lazy read in the old validator path); the branch does not fix it though the task, the docstrings and the rule text claim it does. Not a regression; a gap against the goal. Fix: `ingest_file` forces one full read of the candidate (a `collect()` of the table as read) so what the engine will meet is met here; add tests for these four files (none exists: the test file has no ragged, non-UTF-8 or quote case, so no test could fail on this).
