## ADR-085: "My View" (T3) Decoupled from Audit Capability + T1/T2 Tier Isolation (2026-08-10)

> **SUPERSEDED, replacement BUILT (2026-11-20, ledger D-0350):** there is no "My view" any more (D-0179). Slice B built the mode switch Exploration | Audit (only with `t3_sandbox_enabled`) and the data choice Source | T1 | T2 | T3 (D-0016, D-0310). Exploration filters change only the table viewed and never a plot (D-0327); audit nodes apply only in Audit mode. This entry no longer describes the app.

> **HISTORICAL in part (superseded by ADR-098, 2026-11-11):** decision 1 below, for *exploration* filters (`applied_filters`), no longer holds: they now preview on every view. The rule for audit-committed nodes (My view only) and decisions 2-3 stay active until ADR-099 is built, which replaces My view by audit mode.
> **SUPERSEDED as the target design (ADR-099 points 1 and 2, 2026-11-11; ADR-105, 2026-11-12, confirmed 2026-11-14):** My view, the scratchpad without the sandbox flag (decision 2) and Send to Audit from My view (decision 3) are replaced by Exploration (table only, data viewed only) and audit mode. This entry describes the app as built until ADR-099 and ADR-105 are built.

**Status:** ACCEPTED. Authority: @dasharch, decided with @evezeyl during live-app testing (`test_plan_2026-06.md` HOM-41/HOM-43).
**Amends:** `ui_implementation_contract.md §4` (Interaction & Event Mapping), `§5` (Theater Layout Model), `§8` (Filter Recipe Builder), `§12a` (T3 Scope Lock). `rules_persona_feature_flags.md` (Group B). `rules_ui_dashboard.md §1`.

**Context.** Live testing surfaced three related defects in the Home tier-toggle / filter model, all
traced to the same underlying confusion: "T3" conflated three distinct concerns — a view, an exploration
capability, and a permanent-save capability — into one flag-gated concept.

**Problem 1 — T3 audit nodes leaked into T1/T2.** `_t3_filter_rows()` and `_t3_drop_columns()`
(`app/handlers/home_theater.py`) returned committed Tier-3 audit nodes unconditionally. Every consumer —
the plot renderer, the data preview, the column selector — applied them with no tier check, so a filter or
column-drop committed to the Pipeline Audit appeared on the T1 and T2 views too, even though those tiers
are documented as the untouched reference the sandbox is compared against (`ui_implementation_contract.md
§5`, §12a).

**Problem 2 — Exploration filters leaked into T1/T2 as well.** The same defect existed one layer up:
`applied_filters` (the plain, non-audited "Apply" filter) was injected into every tier's rendering with no
gate at all — not a regression from Problem 1's fix, pre-existing behaviour that testing happened to
surface at the same time. Once a filter was applied for exploration, there was no way to see what T1 or T2
looked like beforehand — the "untouched reference" promise was broken by exploration, not just by audit.

**Problem 3 — Reaching "My view" required audit capability to be enabled at all.** The tier toggle only
offered a third option (labelled "My view" in the UI) `if bootloader.is_enabled("t3_sandbox_enabled")`.
Configs without that flag (`pipeline-exploration-simple_template.yaml`) had a Filters panel but nowhere for
a filter to actually show once you conceptually wanted a "look at my changes" surface distinct from the
frozen T1/T2 references — and once `_filter_apply` was fixed to route all commits through `applied_filters`
(HOM-43), that surface became load-bearing rather than optional.

**Decision.**

1. **T1 and T2 are permanently pure — no exploration filter, no audit-committed filter, no column drop,
   ever shows on either tier**, in any configuration. Both `_group_plot_handler` and `home_data_preview`
   now compute filter/drop rows only when `tier_toggle.get() == "T3"`; on T1/T2 the effective filter list
   is unconditionally empty. `home_col_selector_ui`'s column list is similarly unaffected by committed
   drops outside "My view". This is the standing invariant future consumers of `applied_filters`,
   `_t3_filter_rows()`, or `_t3_drop_columns()` must preserve.

2. **"My view" (T3) is decoupled from audit capability.** The tier toggle now offers "My view" whenever the
   Filters panel exists at all (`interactivity_enabled`) — not only when `t3_sandbox_enabled` is on
   (`home_theater.py` `tier_choices`). Without `t3_sandbox_enabled`, "My view" is a pure scratchpad: filters
   apply and render there, but there is no Send to Audit button, no propagation modal, and no right sidebar
   — nothing persists beyond the session and nothing is ever written to an audit trail. With
   `t3_sandbox_enabled`, the identical view additionally gains the permanent-save path. One view, one
   mental model, two capability levels depending on config — instead of a tier that only exists for
   advanced configs and a separate, undocumented "nowhere to explore" gap for simpler ones.

3. **Apply and Send to Audit are two distinct actions, not one button whose meaning changes by tier.**
   `filter_apply` always commits to `applied_filters` (exploration, "My view" only per Decision 1, never
   audited). `filter_send_to_audit` (new) carries the promotion logic `filter_apply`'s T3 branch used to
   hold (primary-key stamping, propagation modal) and is rendered — and defensively re-checked in its own
   handler — only when **both** `tier_toggle == "T3"` **and** `t3_sandbox_enabled`. This mirrors the
   pattern already used for column drops (`preview_col_selector` = explore/view-only, `col_drop_to_audit` =
   commit); filters now follow the same two-step shape instead of a special case.

4. **Terminology: "Audit," not "Make Permanent."** The button keeps the word "Audit" (`Send to Audit`) to
   stay consistent with the existing "Pipeline Audit" right-sidebar panel name, rather than introduce a
   second term for the same concept. Both buttons carry a `title=` hover tooltip spelling out the
   consequence in plain language, since the label alone was judged insufficient for non-technical users.

**Consequences.**
- `rules_persona_feature_flags.md` Group B: `t3_sandbox_enabled` no longer gates the tier-toggle option
  itself — it gates only the audit UI (Send to Audit button, right sidebar Pipeline Audit panel,
  propagation modal). The tier toggle's third option is gated by `interactivity_enabled` alone. The Full
  Flag Matrix's "Tier toggle T3" row needs a note: `pipeline-exploration-simple` now shows "My view" too,
  as a scratchpad without save capability.
- `ui_implementation_contract.md §4/§5/§8/§12a` need the tier-isolation invariant (Decision 1) and the
  view/capability split (Decision 2) folded in — the current text still describes T3 as a single
  flag-gated concept.
- `test_plan_2026-06.md` CFG-02 (`pipeline-exploration-simple_template.yaml`) expectation changes: "My
  view" tier option now present; "Send to Audit" / right sidebar still absent.
- **Still open (not part of this ADR):** no on-screen "Viewing: T1 / T2 / My view" indicator yet
  (`test_plan_2026-06.md` HOM-40, HOM-42) — tracked separately, not blocking.
- Verification: `from app.src.main import app` clean; `app/tests/test_filter_operators.py` 24/24 pass;
  `test_shiny_smoke.py` 14 passed / 3 skipped (unchanged baseline, `qa` persona — which has
  `t3_sandbox_enabled: true`, so the scratchpad-only path per Decision 2 is not yet exercised by the

  (Decision 2) not yet tested live under `pipeline-exploration-simple_template.yaml`.
