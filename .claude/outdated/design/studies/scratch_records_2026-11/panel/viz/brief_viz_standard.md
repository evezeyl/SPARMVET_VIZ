## The questions
V1. **Names.** 191 components use plotnine's own names; 22 names exist in no plotnine; nothing says "exactly plotnine" or "ours". A keep the names, add a registry field (`exact` / `modified` / `own`) shown in the help and the checker. B prefix every name as the data side does (`plotnine_geom_point`, `modif_...`): every recipe, gallery example, test recipe and doc changes. C prefix only the names that are not plotnine's.
V2. **What a wrapper may do.** 125 components pass straight through, 66 add logic, no marker, no test compares with plotnine. A an "exact" component must equal the direct plotnine call, proved by a test for each; a "modified" one states its change in its description. B leave.
V3. **Where the parameter list comes from.** Hand-written today; 13 to 15 declared parameters are refused by plotnine; 122 components accept any extra parameter. A read the parameters from plotnine at registration (as the Polars actions do), with a list of what is not exposed and why. B keep hand-written, with a test that compares with plotnine. C names from plotnine, descriptions and options by hand.
V4. **Judging a layer's parameters.** Today only names are compared; `size: big` passes the checker and fails later with a raw TypeError. A one rule set (unknown key, required, shape, options, rules), as `step_problems`, called by the checker and by the engine. B in the checker only. C leave. Also: keep `allow_extra_params` or make every component strict.
V5. **The same check everywhere.** HOME and Blueprint give the checker no argument catalogue and no theme list, so a wrong parameter or an unknown theme passes there and is refused in the gallery. A give the full catalogue everywhere (HOME's gate then refuses recipes it accepts today). B keep.
V6. **Silent paths** (7 found: `element_text` without target dropped; `guide_*` without mapping and `position_*` without a layer only print; `annotate` without geom returns the plot, and a test asserts it; a filter with an unknown operator or column is ignored; an unknown spec key is ignored at render). A each becomes an error, as on the data side ("an action that cannot act fails"). B each becomes a warning the user sees. C case by case.
V7. **Errors.** Some errors come from plotnine unwrapped, and only when the picture is drawn. A the factory draws inside `render` and turns every error into one form (what, which plot and layer, how to fix). B leave.
V8. **`plot_engine`.** Declared in every recipe, read by nothing. A the factory reads it and refuses an engine it does not implement; the export records the plotnine version. B checker only, as now.
V9. **Parity with plotnine.** Not met: 29 plotnine objects have no component, and the 12 `colour` spellings are refused. A keep "MUST" and reach it (pass-through components generated from plotnine). B replace the rule: what is registered is exact, what is missing is listed, a test reports new plotnine objects at an upgrade. Spelling: accept both `color` and `colour`, or one spelling with a "did you mean".
V10. **Tests and test recipes.** 194 test recipes are in the old form (0 pass the checker); the integrity suite cannot run; no test fails when a component has no test; the README says "98% pass". A migrate the 194 files to format 1 with a tool and replace the suite by pytest driven by the registry (as the transformer did). V11. **The seed.** Jitter is seeded by default (0); the seed is not written anywhere a reader sees. A the export records the seed used, and the checker advises to pin `random_state` when a random component is used. B as now.
V12. **Order.** This work against the HOME rebuild, the tier-3 reader (R1) and FILTER-UNIFY-1: before, after, or which parts first.
