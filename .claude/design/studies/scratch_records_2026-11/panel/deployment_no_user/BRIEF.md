## The cases to design for
(a) A static page: one recipe shows data that is refreshed every week and pushed into a directory, with several data files.
(b) A pipeline (usegalaxy, IRIDA, any workflow) that starts the app for one run: it needs a temporary place the app can read and write and the user cannot.
(c) A static deployment that names several data files and where each is fetched from.
Cases she did not name, to cover as well: several refreshed data folders; a failed or partial refresh while the app runs; two copies of the app on one folder; a refresh that changes the columns; a deployment where nothing at all can be written.
