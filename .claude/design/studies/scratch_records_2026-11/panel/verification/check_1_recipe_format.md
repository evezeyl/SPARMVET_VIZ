- Errors raise or are reported, never exit (D-0002, D-0029): `app/modules/data_analysis_recipe_validator.py:257-268` returns problems, and refuses a recipe whose check did not cover `structure, actions, components` (`:48`, `:260-266`). That is honest (D-0050).
- **F1 (DEVIATED, formulas of `polars_with_columns` are not checked by the checker).** DEC44 (spec line 782): "formula check below, in the checker (ST06) and at the three sites"; spec line 628: ST06 "a formula uses an operation outside the allowed list". D-0030 "formulas only from an allowed list". The checker applies ST06 only to a parameter with `widget: expression` or a mapping with `value_widget: expression` (`recipe_check.py:558-571`). The real schema of `polars_with_columns` has `named_exprs: {widget: mapping}` without `value_widget` (`polars_calls.py:81`), and `polars_remove` `predicates` is a list without it (checked: `checker_catalogs()` scan, ran). Example (ran): `named_exprs: {z: "__import__('os').system('id')"}` gives **E=[]** from `check_recipe_file`; `formula_problems` on the same text returns two problems. At run time it is refused (ran: `_with_columns` raises `TransformationError "The formula ... is refused: the name '__import__' is not allowed"`), so there is no code execution; the harm is a recipe that Blueprint and HOME's gate accept and that fails only when built, which is what the checker is for (DEC03, "checked first"). Since when: `159ffe78` (2026-11-13, the 37 `polars_` actions); the checker's own test uses a made-up param `exprs` with `value_widget` (`libs/utils/tests/test_recipe_check.py:21`), so it cannot see the gap. Fix: put `"value_widget": "expression"` on `named_exprs` (`polars_calls.py:81`) and on the `predicates` of `polars_remove`, add a test that reads the REAL `ACTION_SCHEMAS`; size small. What it could break: a shipped recipe with a formula outside the list: I ran `formula_problems` on all 21 `polars_with_columns` formulas of the shipped recipes: 0 refused, so nothing shipped breaks (ran, `check1_formulas.py`). Not checked: formulas inside other parameters.
- **F2 (DEVIATED, three writers judge their output with a partial check).** `check_recipe` without `catalogs` checks no action and no plot component (`recipe_check.py:185-187`, coverage then lacks `actions`); I ran a recipe with `keep_columns` and it passed (ran, first sweep). Three places call it without catalogs: `libs/viz_gallery/src/viz_gallery/gallery_manager.py:193` (`submit_example`; no caller outside tests found, read), `assets/scripts/convert_gallery_examples.py:141`, `assets/scripts/create_data_analysis_recipe.py:196` (both write recipe files). Against D-0050 "No silent error" and DEC03 "one checker, for every user"; the app's own gate does it right and refuses a partial check (`validator.py:260`). Since `5a7ab37b`..`ce373923` (2026-11-13/14). What a user suffers: a written recipe or gallery example is called valid while a layer or action name was never looked at (reasoned: the generators use registered names today, so I found no wrong file; I did not generate one). Fix: pass `checker_catalogs()` in the two scripts (tier 3, allowed to import the app layer) and make `submit_example` take `catalogs` like `check_examples` does; size small to medium (the gallery library may not import the app layer, so the catalogs come in as a parameter). Could break: a generated example that today passes the partial check may be refused (that is the aim).
- Cannot see: classes of error the checker never looks for; the profiles `build` and `audit`; the 30 commits one by one.
