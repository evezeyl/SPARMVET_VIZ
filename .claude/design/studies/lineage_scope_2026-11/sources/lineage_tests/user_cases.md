## A. The user's cases (what she does; what she expects; the lines; what misleads)
- **A1 Remove one sample everywhere** (`sample_id` is none of `S7`, viewed in MLST with metadata). Lines, all ticked: the metadata source (reach 6+ tables, about a dozen plots), the MLST source, MLST with metadata T1, T2, the other sources and tables that hold `sample_id`, "Only this plot". Misleads: a long list (20 to 30 lines, estimate); "reach" read as "rows removed" (with a left join the sample stays where the other source drives).
- **A2 One sample from one plot only**: untick all but "Only this plot: mlst_bar". `year_distribution` (same table) must stay the same; the summary must say so.
- **A3 Keep one country** (`country` is Norway). A filter at the metadata source only blanks `country` in tables driven by another source; it does not remove their rows.
- **A4 A number filter where the column is a number in one place and text in another** (`year > 2022`): the demo has no table where `year` itself is text (fixture). At MLST with metadata T2 the recipe already keeps 2023 to 2025: the line should say "your step removes 0 more rows here". `era` is built from `year` at T2: a T1 filter changes legends: "picture changed".
- **A4b Decimal against whole number** (`L50 >= 8.5`): the Quast source line says "decimal number"; the QA L50 integer line says "whole number: decimals were cut off by a step of the recipe; the same condition can keep different rows here" (8.7 became 8).
- **A5 Drop a column** (`source`, `serotype`): every place where it exists, plus per place "plots that use it will break"; `sample_id` (a join key) is refused and must not be an ordinary tick line; "table changed, picture the same" for a plot that does not draw it.
- **A6 A column of one source only** (`serotype`, `VF_protein`): a SHORT list; the test must show it is not padded with tables that lack the column.
- **A7 A renamed column** (`phenotype` in ST22 Anchor): "ResFinder (source file): here the column is called `predicted_phenotype`"; "ST22 Anchor, T1: called `phenotype`". And the case-only difference (`selected_virulence_genes` / `Selected_Virulence_Genes`).
- **A8 A column that appears twice after a join** (`x` and `x_right`; fixture): two different columns, each its own line with its full name.
- **A9 A table shared by six plots** (fixture): the table line reaches 6 plots (names on demand); "Only this plot" reaches 1. Misleads: wanting one plot, ticking the table line changes five other pictures.
- **A10 A plot with its own steps** (fixture): "the table of this plot after its own steps" and "Only this plot" must be ONE line, named.
- **A11 Unticking everything**: cannot apply: "Nothing is ticked, so this step would change nothing. Tick at least one place."
- **A12 A place and its dependant both ticked**: this is the DEFAULT (all start ticked), not an edge case: several steps doing the same; the dialog should show "removes 0 rows here that the ticked place above does not already remove".
- **A13 The same step twice**: a refusal, or "This step is already in your audit steps (step 2). Writing it again removes 0 rows."
- **A14 Remove step**: every table and plot exactly as before.
- **A15 A data file missing**: the other places listed; the places that need the file grey: "Not available: Quast with metadata cannot be checked because the data file Quast.tsv was not found. Its plots (assembly_quality_dotplot, miaou) cannot be checked."; the summary: "2 places could not be checked: the step is not written there and they are not in the counts."
- **A16 A very long list**: users stop reading at about 12 lines. Order, always the same: (1) the place she is looking at first, marked "you are here"; (2) groups in the order of the data flow: source files, tables, plots, each in the recipe's order; (3) each group with a header and a count ("Source files, 8 of 8 ticked"); (4) one sentence at the top: "This step will be written in 27 places. Untick the places you do not want." Not alphabetical; not grouped only by path.

## B. The words
- ONE vocabulary: a line names the table as the data choice shows it (the recipe's label and Source / T1 / T2 / T3), so she can open the line's table and see the same rows. The three words explained once at the top of the dialog ("T1 = the table after its first steps", "T2 = after its second steps", "T3 = the table of one plot after the plot's own steps").
- A table without steps at T2: "MLST with metadata, T1 (also what you see at T2: no steps of its own there)"; T2 is then not a line.
- Normal: "[x] MLST with metadata, T2: reaches 2 plots (mlst_bar, year_distribution)."
- Type differs (ticked): "[x] QA L50 integer, T1: L50 is a whole number here. At the place you chose it is a decimal number. The same condition can keep different rows."
- Renamed: "[x] ResFinder (source): here the column is called `predicted_phenotype`; you chose `phenotype`. The step is written with the name used here."
- The column no longer exists: NOT a line (nowhere to write the step); a note under the line that reaches it: "Not a place: in Quast with metadata the column `year` is no longer there (not kept when the measures were turned into rows). The table may still change through its source; see the row count below."
- Grey: "[ ] (not available) Quast with metadata: the data file Quast.tsv was not found. It is not counted below."
- Reach: "Reaches 3 tables and 5 plots", defined once as "tables and plots built from this place, directly or through another table"; "show which" lists the names; never a bare count; it does NOT say rows are removed.
- Only this plot: "[x] Only this plot: mlst_bar: written in this plot's own table. Other plots that read MLST with metadata (year_distribution) are not changed."
- Before confirming: per table "rows removed" (with "0, the step finds nothing here"); per plot "table changed / table the same" and "picture changed / picture the same"; "1 place could not be checked."
- Words NOT to use: lineage, node, tier, schema, upstream, downstream, cast, "key" without "join key: the column that links the tables"; T1/T2/T3 only with the one-time explanation. Use "place" and "Remove step".

## C. What a test must check from the user's side (each a browser test)
C1 every line names a table or plot she can open in the data choice. C2 for each line ticked alone, the rows that disappear from that table equal the "rows removed" announced (not the reach). C3 the dialog opened twice with the same choice gives the same lines in the same order; stable across a restart. C4 after "Remove step" every table and plot equals the state before, row for row. C5 a table with no steps at T2 gives no T2 line; with steps, two lines (MLST with metadata: two; a join without second steps: one). C6 a join no plot reads is not a line; adding a plot on it makes it appear. C7 the reach count equals the number of distinct tables and plots that depend on the place, and "show which" lists exactly that many names. C8 "Only this plot" appears for every plot, reaches exactly 1, and ticking only it changes no other plot's table. C9 a missing data file gives grey lines with the reason; the rest stay tickable; the summary says how many could not be checked. C10 a line where the type differs is ticked and the type is written; a line with another name shows that name. C11 all lines start ticked; "nothing ticked" blocks the confirmation. C12 `L50 >= 8.5`: the rows kept at the decimal place and at the whole-number place are both reported. C13 the same recipe and data give the same lines on two machines. C14 a step that duplicates an existing one is refused or reported "0 rows here". C15 the drop of a join key is never an ordinary tick line. C16 the same column chosen from two different tables gives the same set of places (only "you are here" moves). C17 the number of lines equals a count computed independently from the recipe; break the walk once and see this test fail.

## D. Pitfalls a non-developer would not see
P1 reach is not row loss (left join keeps, inner join drops). P2 a filter at a source is not the same as on the joined table. P3 a renamed column hides the match. P4 a table line touches plots she did not choose. P5 the same condition on two types. P6 redundancy by default (all ticked: several steps doing the same). P7 a step the recipe already does (0 rows removed here). P8 a column turned into rows cannot be filtered as a column there. P9 a plot that uses a dropped column breaks. P10 a missing file makes the list shorter, not wrong. P11 a long list invites "tick all and click". P12 two vocabularies. P13 a pivot or unpivot may make the dialog read rows: if the list is slow she must be told why.
