## How to read the tables

- One table per part. Columns: **DECIDED** (her words between quotation marks, with the ledger number) | **BUILT today** (what the code on `dev` does, with file:line) | **the difference** | **kind**.
- The first column `id` is only a label, so that the other files can point to a row (for example `D2`).
- **Kind** is one of: AGREES; NOT BUILT; BUILT BUT OLD (a behaviour from before a decision that replaced it); BUILT BUT PROVISIONAL (a builder's choice she never took); CONTRADICTS (the code does the opposite of a decision).
- Where a decision was a letter ("A", "B", "C"), the ledger's wording of the option she chose is given, marked as such: those words are the review session's, not hers.
- A sentence marked **reading** is the review session's or the coordinator's reading of her words, not her words.
- Evidence labels: **[read by me]** = read in the code on 2026-11-22 by the author of version 1 or of version 2; **[collected]** = taken from `BUILT_audit_lineage.md` or `BUILT_format_export_names.md` (read by an agent on 2026-11-22), not re-read; **[review]** = confirmed by the review of the code claims (`REVIEW_built.md` of the coordinator, main tree); **[run, trial]** = a run of the panel of 2026-11-22 (`tmpAI/panel/default_ticks/TRIAL.md`); **[run, review]** = a run of the two reviews of the untick branch (`EVIDENCE_untick_branch_reviews.md`).
- Words: the **entity key** is the column the recipe declares with `is_entity_key` (D-0313; "remember we are data agnostic so sample id is the example", D-0512); the **entity** is what one value of that key names (my wording; no decision defines it). On the demo recipe `1_test_data_ST22_dummy` the entity is a sample and the entity key is `sample_id`.
- D-0510 to D-0526 are committed in the ledger on `dev` (main tree) since the evening of 2026-11-22.
