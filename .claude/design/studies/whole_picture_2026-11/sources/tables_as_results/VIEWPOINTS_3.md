## Scientist (V = verified by reading or run; R = reasoned)
(c) Export. Today's T3 file is only the audited table, `<ds>/T3_data_<plot>.tsv` (`export_handlers.py:1417-1440`), built as `audited_frame(materialize_tier3(...), nodes)`; contract 7.2 rule 4 says the same (V). The unaudited result is not exported. The file is written only when the plot has T3 steps or audit steps (`t3_table_plots`, `:1095`): a table entry with neither would get no file (V). Name: from the id, not from `ui_label` (a label rename would rename the file between exports) (R); the label inside the README. Suggested path `results/<id>.tsv`. README and report list "Result: <label> (<id>)" with the row count and the audit state. The report must include the table; today figures only. The key check applies unchanged.
(d) Audit, by a small run (`scientist/diff.py`, V): removing one sample changed group A's mean from 23.67 to 30.5; only the group key lines the rows up; a row-by-row diff is readable only when the summary has a key column and the join is full-outer on it; removing every sample of group C makes the row vanish; a positional diff would misalign silently; with no key (a one-row summary) the only honest diff is before and after (23.2 with n=5 became 26.5 with n=4). Smallest honest minimum: rows and columns before and after, cells changed, groups added or removed; n per group only when the recipe has an n column (do not invent one). Compute the diff from the two tables, never from the audit step text. d1 teaches most and fits a table; it costs a key choice and the app must not guess one. d2 is cheap but only says that something changed. d3 works if rows are matched by key. d4 hides the size of the change. If a diff is built, export both tables by name; or the baseline recipe plus the audit recipe (D-0478) lets a reviewer rebuild the original: say plainly which is shipped.
(b) The cap of 100 is applied after the audit and filters (`home_theater.py:1692`); the title only says "max. first 100 rows" (`:1665`). A result table must say "Showing 100 of N rows". Exploration filters and the column selector (`:1688-1700`) must be labelled "view only" under a result sub-tab, or the screen differs from the export.
(3) Is the last stage always the result? No (R): an author may add a tier 3 only to sort, select display columns, round, or make `mean ± sd` text columns; the last stage then loses the unrounded values a reviewer needs. A Result must be shown with its last-stage steps listed.
Flags: a table entry with no T3 or audit steps would be missing from the export; a silent cap at 100 rows; view-only filters; NaN, ties and order are not fixed in summaries.
