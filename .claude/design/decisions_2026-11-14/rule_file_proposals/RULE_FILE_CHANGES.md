# Rule file changes: one dated list (kept from 2026-11-15)

## What this list is

The rule files in `.claude/rules/` tell the agents how to work in this project. This list names every change to them: changes that are only proposed, and changes that were already made.

## Why it exists

Eve decided on 2026-11-15: no rule file changes without her agreement, and every change must be traceable. This list is the one place where she can see all of them.

## How to read one row

- **R-number:** the number of the row in this list (R001, R002 ...).
- **Rule file and line:** where the text is today (commit 5be9f103, 2026-11-15).
- **Old text and new text:** a short quote of what it says now, and what it would say.
- **Reason:** why, in one sentence.
- **Source decision:** who decided it and where it is written down. "ADR" is a recorded architecture decision (file `.claude/knowledge/architecture_decisions.md`). "DEC" is a numbered decision of the recipe format (file `.claude/design/recipe_format_spec.md`). "M" is a message block of the agent channel. "D" is a numbered question in `.claude/design/decisions_2026-11-14/proposals_for_eve.md`. "Proposal file" is a file in `.claude/design/decisions_2026-11-14/rule_file_proposals/`.
- **Status:** see below.

Two technical words in the rows: a "thin re-export shim" is a file that only passes names on from another file; the "TYPE_CHECKING exception" is an import that only the type checker reads and that never runs when the program runs.

## What each status means

- **proposed:** written down, not applied. Waits for Eve's yes.
- **proposed, question for Eve:** two valid choices exist; Eve chooses (see `doc_links.proposal.md`).
- **proposed, wording not written yet:** a reading found a rule text that contradicts Eve's two-recipes rule of 2026-11-15 (the original recipe is never edited; the audit only adds steps). No new wording exists yet.
- **applied, confirmation recorded elsewhere:** the edit was made and a task, a decision or a channel block records Eve's yes.
- **applied, Eve named only in the rule text:** the edit was made; the only trace of her yes is a sentence inside the rule text itself. No separate record was found.
- **applied, no confirmation found:** the edit was made and no record names her yes for that edit.
- **confirmed by Eve 2026-11-16, applied:** her yes is recorded in the agent channel (M150) and in the ledger line named in the row; the edit and the row are in one commit.

## How the list is kept

- One row per change. Sorted by rule file, then line.
- **Who adds a row:** the agent that proposes or makes a change. A change that is not in this list does not go into `.claude/rules/`.
- **When:** at the proposal (status "proposed"); when Eve says yes ("confirmed by Eve <date>", with where she said it); in the same commit as the edit ("applied <commit>"). The reviewer checks that every changed line in `.claude/rules/` has a row.
- The long text of each proposal stays in its proposal file; this list is the index.
- Applied rows were found in git (changes since 2026-11-12, plus commit 6349ba7f of 2026-11-12).
