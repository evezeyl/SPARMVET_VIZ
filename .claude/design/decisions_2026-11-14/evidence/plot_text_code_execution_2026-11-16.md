# Plot texts that run code: the sweep and how each site is closed (PLOT-TEXT-RUNS-CODE-1, 2026-11-16)

Found by a data scientist: the `formula` of a smoother is evaluated as Python by plotnine. This file answers "where else can a text of a recipe, a plot spec, a `plot_defaults` block, a palette or theme, an audit step or a session file reach something that runs it as Python", and how each reachable place is closed. The decision is the one already taken (Eve, 2026-11-13 and 2026-11-15; FORMULA-SAFETY-1; recipe format spec section 15, check ST06; ADR-099 point 14): a text of a recipe must not be able to run code; the text is read as syntax and never run before it passes. Nothing new was decided here.

**RUN** = I ran it. **READ** = read in code. Versions: plotnine 0.15.4, patsy 1.0.2, statsmodels 0.14.6, mizani 0.14.4, numpy 2.4.4, pandas 3.0.2, Polars 1.40.1, Quarto 1.8.27.

## How it was tested (RUN)

A "harmless attempt" is a text that, if something runs it, writes a small file (`marker.txt`) under `tmpAI/` of the worktree: `__import__('pathlib').Path(<marker>).write_text('x')`, wrapped as `len(...) * 0` where a number is expected. After each attempt the marker is looked for.

1. **Brute force over the registry, against the UNCHANGED code** (commit `3d69e14f`, copied with `git archive` to `tmpAI/baseline`, so my own changes cannot hide a hole): every one of the 191 registered plot components, every argument it accepts (read from plotnine and the schema), each given the text as a text, as a list of one text and as a dictionary of one text. The 11 components whose arguments cannot be listed (`annotate`, `element_line`, `element_rect`, `element_text`, `facet_labeller`, `facet_margins`, `facet_scales`, `facet_space`, `stat_identity`, `theme_custom`, `theme_legend_position`) were also tried with 44 common argument names. Scripts: `tmpAI/probe/probe_all.py`, `probe_free.py`, `run_all.sh baseline` (git-ignored scratch; they write only under `tmpAI/probe/`).
2. **By hand, against the unchanged code** (`tmpAI/probe/probe_sites.py`): the spec-level keys (`mapping` text, `facet_by`, `theme`, `palette`), `plot_defaults` (`palette`, `theme`, `default_font_family`, `legend_position`) and the T3 `aesthetic_override` (`fill_palette`, `color`, `theme`, `shape`).
3. **Reading** every `eval`, `exec`, `compile`, `.query(`, `.eval(`, `pickle`, `yaml.load`, `subprocess`, `importlib` in `libs/*/src` and `app/` (list below).

## One more site, closed in the fix round: `report.qmd` of an export (REACHED)

The export writes `report.qmd` from texts of the session and the recipe (`app/handlers/export_handlers.py`: the plot `title`, ids, labels, the audit step `reason` and `params`, the processing issues, the lineage labels) and then runs `quarto render` on it on the machine that runs the app. Until the fix round the texts were inserted raw (only `|` was escaped in the reason). A text with a new line and a fenced Python cell, or an inline `` `{python} expr` `` once the Python engine is on, is a code cell for Quarto.

RUN (first proof, 2026-11-16): the T3 Audit Trail row built with the handler's line construction, rendered as the handler does with `QUARTO_PYTHON=/usr/bin/python3` (the interpreter on this machine that has Jupyter): the cell ran and wrote its marker. The fix-round test `app/tests/test_export_report_texts.py` repeats it as a control (a raw text writes the marker for a fence, an inline expression, and an inline expression inside a sentence), and then shows the three closed ways below. With the default interpreter of this machine (Homebrew Python, no `yaml`) Quarto stops before running a cell, so the exposure depends on how the host is set up; the control skips with that reason where Jupyter is missing.

Decision that applies (Eve 2026-11-13): a text of a recipe must never run code. Closed both ways, because neither changes what a user sees:
- **(a) One module makes every inserted text harmless:** `app/modules/qmd_text.py` (`plain`, `code`, `yaml_string`, `mermaid_label`). `plain` writes one line and puts a backslash before every character that Markdown, a table, a Pandoc attribute, a shortcode, a citation, a formula, raw HTML or a code fence could read (an underscore only where it could start emphasis, so `multi_resistance_by_country` is unchanged); `code` makes an inline code span that cannot be closed from inside, pads a text that starts with `{` (so it is not an inline expression) and defuses `{{<` (Quarto reads a shortcode, such as `include` or `env`, even inside a code span: RUN); `yaml_string` is the front matter's quoted string; `mermaid_label` is for the diagram. A text with a `|` in a table cell is written with `plain` (a code span cannot show it: RUN). The same text reads the same in the rendered report (RUN: paragraph, table cell, heading and code span, for an underscore, a star, a percent sign, a dollar sign, a backtick, a pipe, a hash, a list marker, brackets, a citation, a superscript, braces; the quotes become typographic quotes as before).
- **(b) The render command has `--no-execute`.** The handler writes no code cell of its own: the only fenced cell in `export_handlers.py` is the Mermaid diagram (a test lists the cells). `app/assets/report_template.qmd` is read by no code (it holds `{python}` cells, but nothing renders it). The diagram still renders with `--no-execute`: RUN in headless Chromium, the page holds one SVG with the node labels (a Mermaid cell is drawn by Quarto's own script, not by an execution engine); the test does it when a browser is installed. A render without a cell uses no engine, so an inline expression is not evaluated either.

Insertion sites in `app/handlers/export_handlers.py` (56 calls of the functions; the lines of the file after the fix): `plot_report_lines` 290, 292, 293 (plot label, the link target, the reason a plot was not drawn, the error file name); `_build_methods_section` 384, 396-401, 405, 415, 423, 429, 434, 442 (plot title, column, operator, values, the range sentence, seed, reason, override keys); the front matter 1492-1494 (title, date, author); Overview 1516-1519 (recipe id, app features, preset, time); dataset to plot table 1527-1528; provenance table 1536-1549 (dataset keys, the stage keys, decision hashes); software and Git rows 1558-1566; plots 1608 (caption: plot title, dataset); data files 1625-1626, 1637 (plots, dataset heading, the folder name in a link); T3 audit trail 1648-1663 (section label, parameters, reason, action); processing issues 1684-1688 (time, component, severity, problem); lineage 1715 (diagram label), 1741-1742 (step table); seed notes 1755. The render command is at 1787 (`"--no-execute"`). The import is line 27, the helper `_quote` lines 279-284. A test (`test_every_text_inserted_into_the_report_goes_through_the_functions`) reads the handler's syntax and fails for any `f"...{value}..."` of the report, and for any line added in another form (see the third fix round), whose value is not a call of these functions or a name that is built from them (a short list of trusted names, each with its reason).

Mutations, each seen failing and restored with `git checkout -- <file>`: the escape removed at the audit reason (the scan fails); `--no-execute` removed (the command test fails); `plain` without the backtick escape (4 tests fail).

## Fixes of the fix round: a facet name, a doubled label

**A facet is handed to plotnine as a list of exact column names.** plotnine reads a facet text such as `~Collection year` with a pattern that stops at the first character that is not a letter, digit or underscore; with a column `Collection` and a column `Collection year` it drew the panels of `Collection` (2 panels, not 3) and said nothing (RUN by the reviewer, repeated here: `facet_by: "Collection year"` and `facets: "~Collection year"`). Now our reader (`utils.plot_text_check.facet_variables`, `facet_sides`, `facet_wrap_spec`) splits a text written by the recipe maker (`a ~ b`, `~ a + b`; the whole text first, when it is a column) into exact names, checked against the data (a name that is not a column is refused in our words with the columns listed), and plotnine gets a list, for `facet_by`, `facet_wrap` (in `registry.get_component`, so that `facet_wrap` stays `exact`), `facet_grid` rows and cols and the formula, `facet_rows` and `facet_cols` (their handlers). Names with a space, a dash, a dot, an accent, a number first are drawn right (`libs/viz_factory/tests/test_facet_exact_names.py`, 73 tests).

**One label.** A fix that starts with `Suggestion:` is shown without `Fix:` (`utils/fix_text.py`, one function): in the factory's error (HOME draws it in the place of the plot and in the Alerts panel; Blueprint's preview shows the same error), in the checker's problem text, in the upload and gate reports (`data_analysis_recipe_validator.py`), and in HOME's Alerts and warning lines. The load gate and Blueprint's Validate read the problem and its tip separately, which already followed the rule (`app/tests/test_suggestion_label.py`).

- **`code()` and an inline expression.** The earlier padding did not stop `` `{python} x` `` (RUN: four tests of `test_export_report_texts.py` failed, `[code-inline]`, `[code-inline_in_text]` and the two `code_table` ones; my earlier report called that file passing because I ran it before I changed the control to switch the Python engine on (`jupyter: python3`, the worst case) and never ran the whole file again; the full run excluded it because the file mentions a browser). - **The front matter.** A title is Markdown, and TeX for a PDF: a recipe file named `\input{/path}` put that file into the PDF title (RUN, control), and `{{< include >}}` stopped the render (RUN). `yaml_string` now writes `plain(text)` as a JSON (YAML) string; `plain` breaks `{{` and `}}` with a zero-width space (Quarto reads the shortcode in the text that Pandoc has already unescaped, and stops at a lone `>}}`) and escapes `>`. Tests render a title with `\input{file}`, `{{< include file >}}` and a mix, to HTML, PDF (xelatex and pdftotext are installed here) and Word, assert that the file's content is not in the document and that the text shows, and the controls show that a title that is only valid YAML does read the file or stop the render. An ordinary id reads the same.
- **The scan sees every way to add a line.** Besides the f-strings, the test reads every expression put into a report list (`qmd_lines = [...]`, `+=`, `.append`, `.extend`; `lines` and `prose_items` in the two helpers; a name that holds a list is followed to what was put into it): `"x " + name`, `.format(...)`, `%`, a variable with a raw value, and any call that is not one of the text functions are refused; ten such forms are tested to fail, six harmless ones to pass. A new helper that builds lines must be added to `LINE_BUILDERS` (its own body is then scanned). The limit: text that reaches a line through a function the scan does not know is refused, not followed; text that never goes through these three places (a new function elsewhere that writes into the report) is not seen. - **One label, everywhere (D-0099).** `fix_prefix` and `fix_label` (`utils/fix_text.py`) are now also used in `PipelineError.format` (`pipeline_error.py:136`), the payload of the Alerts renderers (`pipeline_error.py:233`), the text of `plots/<id>_ERROR.txt` in an export (`export_handlers.py:276`), and the join verdict of Blueprint (`blueprint_handlers.py:2296`; its fixes are written "Pick ..." today, so nothing was doubled there: checked, the rule is applied for the day one starts with `Suggestion:`). The lines of the last round: `audit_stack.py:30, 925` (the Alerts panel), `home_theater.py:48, 180` (the warning line).

## The checks (what is built)

| Part | File | What it does |
|---|---|---|
| grammar of a smoother formula | `libs/utils/src/utils/formula_check.py` `smoother_formula_problems` | reads the text as tokens, never runs it. Allowed: the names `x` and `y`, numbers, `+ - * / : **` and the comparisons, brackets, `~` exactly once, the patsy functions `I C bs cr cc te center standardize scale`, the math names of `MATH_FUNCTIONS` bare or as `np.name`, `numpy.name`, `math.name`, `pi`, `e`; a call may have options whose value is a number or `True` or `False`; an exponent is a number up to 100 and not repeated; at most 400 parts and 2000 characters. Refused: any other name or function (`getattr`, `eval`, `open`, `__import__`, `np.load`), a text in quotes, a list, a subscript (`x[0]`), an attribute (`x.__class__`), a keyword or `*` argument, `lambda`, a conditional, a second `~` |
| the layer check | `libs/utils/src/utils/plot_text_check.py` `layer_text_problems` | applies the grammar to the argument `formula` of any component; checks the facet variables of the `facet_*` components (`facets`, `rows`, `cols`; the text is split at `~` and `+` as plotnine does): without the data a plain column name (letters, digits, underscore, space, dot, dash); with the data an exact column; checks the `fun` of `stat_function` |
| the checker | `libs/utils/src/utils/recipe_check.py` | check **PS06** on every layer, and on `mapping.facet_by`; needs no catalogue, so HOME's load gate, Blueprint's Validate, the importer and the gallery check all show it |
| the factory | `libs/viz_factory/src/viz_factory/registry.py` `get_component` / `refuse_unsafe_texts` | every component is handed out inside the same check, with the columns of the data; a refusal is a `CannotAct`, which the factory turns into the one error form that names the plot and the layer |
| the environment | `libs/viz_factory/src/viz_factory/checked_plot.py` `plot_environment` | plotnine evaluated texts in the frame of `VizFactory.render`, so the table, the recipe and `self` were visible by name. It now sees numpy maths only. Python's builtins stay visible to any `eval`: the check is what keeps them out of reach. A side effect that a recipe maker will like: `y ~ np.log(x)` and `y ~ log(x)` now work (before, they stopped with "name 'np' is not defined") |

The message reads: `Plot 'p', layer 2 (geom_smooth): the formula 'y ~ I(eval(x))' is refused: the function 'eval' is not allowed in a smoother formula. Suggestion: write one of the allowed functions: ...` (the checker prints `[PS06]` and the path `analysis_groups.g.plots.p.spec.layers[2].params.formula`). (Before the fix round the label read `Fix: Suggestion:`.)

## The smoother formulas (RUN through the factory and plotnine, `y ~ ...`, method `lm`)

Worked before the change and work now (the same result): `y ~ x`, `y ~ x + I(x**2)`, `y ~ x + I(x**2) + I(x**3)`, `y ~ x - 1`, `y ~ 0 + x`, `y ~ 1 + x`, `y ~ x ** 2`, `y ~ I(x ** 2)`, `y ~ I(x**0.5)`, `y ~ I(1/x)`, `y ~ I(x > 5)`, `y ~ I(x*2)`, `y ~ (x + 1)`, `y ~ I(x**2) + x`, `y ~ bs(x, df=4)`, `y ~ cr(x, df=4)`, `y ~ center(x)`, `y ~ standardize(x)`, `y ~ scale(x)`.

Did not work before (a name error, because the formula was evaluated in the frame of `render`, which has no `np`), work now: `y ~ np.log(x)`, `y ~ log(x)`, `y ~ I(np.log(x))`, `np.log(y) ~ np.log(x)`, `y ~ np.log10(x)`, `y ~ np.exp(x/10)`, `y ~ np.sqrt(x)`, `y ~ I(np.sqrt(x))`, `y ~ math.log(x)`, `y ~ I(np.abs(x))`, `y ~ np.abs(x)`, `y ~ np.log(x + 1)`, `y ~ np.sin(x)`, `y ~ np.sinh(x)`.

Do not work before and after (plotnine or patsy refuses them, or the name is outside the list): `y ~ C(g)`, `y ~ x*g`, `y ~ x:g`, `y ~ x + g` (a smoother sees only `x` and `y`), `y ~ poly(x, 2)` (patsy has no `poly`), `y ~ 1/x`, `y ~ x + I(x^2)`, `~ x`, `x`, and, refused by the allow-list, `np.power`, `np.log1p`, `np.arcsinh`.

**No shipped recipe, template, retest recipe or gallery example uses a `formula`** (grep of every `*.yaml`: no `formula:` key), so the allow-list refuses nothing that ships. Facets that ship use the forms `col`, `row ~ col`, `~ col` and `facet_by`; all pass.

## What was not checked

- The known limit of section 15 holds here too: an allowed formula can still be slow or large (for example `bs(x, df=100000000)` asks patsy for a huge matrix). Nothing here limits the size of a number given as an option; it is not code execution.

- The real export handler is run end to end only by the browser test `app/tests/test_export_download.py` (ordinary texts: the bundle's content is unchanged); the hostile texts are tested on the text functions, on the handler's syntax and on Quarto, not through a Shiny session.
- Combinations of two texts in one layer (each argument was tried alone).
- A plotnine, patsy or mizani release other than the installed ones: a test (`libs/viz_factory/tests/test_plot_text_runs_no_code.py`) would have to be extended by the brute-force script; the script is scratch and not in the repository. A new plotnine release that evaluates another argument is not caught by the tests.
- `facet_by` in `plot_defaults` or in a T3 override: neither takes it.
